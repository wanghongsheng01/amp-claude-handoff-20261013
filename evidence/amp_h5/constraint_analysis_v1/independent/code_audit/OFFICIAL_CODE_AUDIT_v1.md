## Official provenance and algorithm evidence

### LSSAMP

The [repository README](https://github.com/dqwang122/LSSAMP/blob/f8f9c7bce63693383818a83cf08639981498ef58/README.md) identifies the accompanying paper, *Accelerating Antimicrobial Peptide Discovery with Latent Sequence-Structure Model*. It describes sequence/secondary-structure modeling and a pretraining/finetuning workflow.

The inspected [ProteinCVQVAE implementation](https://github.com/dqwang122/LSSAMP/blob/f8f9c7bce63693383818a83cf08639981498ef58/src/models/model_builder.py#L344) encodes inputs into quantized latent codes and conditions its decoder on projected code embeddings. Its [sample method, lines 460–498](https://github.com/dqwang122/LSSAMP/blob/f8f9c7bce63693383818a83cf08639981498ef58/src/models/model_builder.py#L460) performs either argmax or multinomial token selection from decoder scores. The inspected method contains no future-validity dynamic program, MH acceptance step or SMC importance correction. This bounded inspection does not assert the absence of every possible constraint feature elsewhere.

The [requirements](https://github.com/dqwang122/LSSAMP/blob/f8f9c7bce63693383818a83cf08639981498ef58/requirements.txt) include torch 1.9.0, unpinned OpenNMT-py, python-Levenshtein, modlamp, seaborn, cmake 3.17.0 and MulticoreTSNE; README specifies Python 3.7. [sample_vae](https://github.com/dqwang122/LSSAMP/blob/f8f9c7bce63693383818a83cf08639981498ef58/src/train_vae.py#L273) selects CPU for visible_gpus=-1, but sample line 479 calls self.cuda(), which invokes module conversion rather than checking its device. Thus the advertised CPU switch alone does not establish a CPU-safe generation path. [Sampling configuration](https://github.com/dqwang122/LSSAMP/blob/f8f9c7bce63693383818a83cf08639981498ef58/configs/lssamp_sample.yml) defaults to GPU 0 and top selection.

### Twisted Sequential Monte Carlo

The [author paper, Section 7](https://arxiv.org/html/2404.17546v1) directly links Silent-Zebra/twisted-smc-lm. The [ICML record](https://proceedings.mlr.press/v235/zhao24c.html) reports learned future-potential twist functions and bidirectional SMC inference evaluation.

Actual [proposal code, lines 256–334](https://github.com/Silent-Zebra/twisted-smc-lm/blob/28d921a7fedd1584a1bbe97aa498a63013585cb5/custom_transformer_prob_utils.py#L256) combines base-model log probability with a twist, samples categorically, and computes normalized proposal log probability. The [SMC step, lines 563–697](https://github.com/Silent-Zebra/twisted-smc-lm/blob/28d921a7fedd1584a1bbe97aa498a63013585cb5/custom_transformer_prob_utils.py#L563) updates log importance weights, log-normalizer estimates, and particles; an ESS criterion uses half the particle count. [losses.py](https://github.com/Silent-Zebra/twisted-smc-lm/blob/28d921a7fedd1584a1bbe97aa498a63013585cb5/losses.py#L78) contains EBM/contrastive twist objectives. [Analytic toy tests](https://github.com/Silent-Zebra/twisted-smc-lm/blob/28d921a7fedd1584a1bbe97aa498a63013585cb5/custom_toy_transformer_and_analytic_tests/TestClass.py#L159) compute optimal twists by enumerating completions, providing a concrete verification reference.

The [official requirements](https://github.com/Silent-Zebra/twisted-smc-lm/blob/28d921a7fedd1584a1bbe97aa498a63013585cb5/requirements.txt) pin JAX 0.4.21, CUDA JAXlib 0.4.21+cuda11.cudnn86, torch 2.1.1+cu118, CUDA libraries, Flax 0.7.5, Optax 0.1.7 and Transformers 4.36.0. README uses Python 3.10.3. This is not an unchanged CPU environment. No runtime or single-thread reproducibility claim follows from inspecting the generic numerical code.

### Constrained Sampling Should Be Easy / CASA

The [NeurIPS 2025 paper](https://papers.nips.cc/paper_files/paper/2025/file/5681251fa039cf49d6d11b906eded1b3-Paper-Conference.pdf) explicitly names large-loris-models/casa in its code footnote, as indexed by the official proceedings search result. Direct PDF retrieval exceeded the web tool's size cap, so that provenance is based on the official search excerpt and the repository's reciprocal paper reference. The [arXiv record](https://arxiv.org/abs/2506.05754) reports valid-output proposals with MH acceptance; the [CASA README](https://github.com/large-loris-models/casa/blob/54a11a6e934c4a9a4248c8ceb092d9e352a3c748/README.md) associates Uniform/Priority/Restart MCMC with this paper. CASA now also implements later CARS and other samplers; these must not all be attributed to the 2025 MCMC paper.

The [MCMC sample loop, lines 156–257](https://github.com/large-loris-models/casa/blob/54a11a6e934c4a9a4248c8ceb092d9e352a3c748/src/casa/samplers/mcmc.py#L156) computes LM likelihood ratios plus reverse/forward proposal ratios, caps acceptance at one, and keeps or replaces the state. [Lines 339–498](https://github.com/large-loris-models/casa/blob/54a11a6e934c4a9a4248c8ceb092d9e352a3c748/src/casa/samplers/mcmc.py#L339) implement restart, uniform and entropy-weighted resampling positions; retain a prefix; regenerate a grammar-constrained suffix; and sum proposal probabilities over compatible prefix positions. This is substantive corrected constrained sampling, beyond a local validity mask.

[pyproject.toml](https://github.com/large-loris-models/casa/blob/54a11a6e934c4a9a4248c8ceb092d9e352a3c748/pyproject.toml) requires Python >=3.12, torch >=2.0, transformers >=4.30, accelerate >=1.10.1, numpy >=1.24, llguidance >=0.7, rich >=14.1 and xgrammar >=0.1. The [LLM wrapper](https://github.com/large-loris-models/casa/blob/54a11a6e934c4a9a4248c8ceb092d9e352a3c748/src/casa/llm.py#L26) accepts a preloaded model/device. Its from_pretrained helper defaults to bfloat16/device_map=auto and contains a secrets.json fallback read. That helper was not invoked and is unsuitable unchanged under the no-credential-read restriction. Small CPU adaptation is an engineering prospect; runtime, native-package compatibility, termination and finite-step target accuracy remain untested.

### Ctrl-G

The [paper](https://arxiv.org/html/2406.13892v1) directly links joshuacnf/Ctrl-G. Independent sub-audit traced [HMM forward/backward operations](https://github.com/joshuacnf/Ctrl-G/blob/379463249c368739f81c46c1e71b8673bfcedf7c/ctrlg/hmm.py#L24), [DFA composition](https://github.com/joshuacnf/Ctrl-G/blob/379463249c368739f81c46c1e71b8673bfcedf7c/ctrlg/dfa.py#L293), and [compiled DFA token/state masks](https://github.com/joshuacnf/Ctrl-G/blob/379463249c368739f81c46c1e71b8673bfcedf7c/ctrlg/dfa.py#L631). [ConstraintLogitsProcessor lines 145–244](https://github.com/joshuacnf/Ctrl-G/blob/379463249c368739f81c46c1e71b8673bfcedf7c/ctrlg/utils.py#L145) builds accepting-state and remaining-length continuation caches. [Lines 246–410](https://github.com/joshuacnf/Ctrl-G/blob/379463249c368739f81c46c1e71b8673bfcedf7c/ctrlg/utils.py#L246) combine constrained versus unconditional HMM logits with the base LLM, including alpha-scaled guidance.

The [README](https://github.com/joshuacnf/Ctrl-G/blob/379463249c368739f81c46c1e71b8673bfcedf7c/README.md#L19) specifies Python 3.11, PyTorch CUDA 12.1, Transformers 4.41.2, huggingface_hub 0.23.4, and FAISS GPU 1.8.0 for distillation; setup.py itself leaves dependencies unspecified. Distillation [selects CUDA](https://github.com/joshuacnf/Ctrl-G/blob/379463249c368739f81c46c1e71b8673bfcedf7c/distillation/sample_data.py#L49), [uses FAISS GPU](https://github.com/joshuacnf/Ctrl-G/blob/379463249c368739f81c46c1e71b8673bfcedf7c/distillation/lvd_hmm.py#L53) and [initializes NCCL](https://github.com/joshuacnf/Ctrl-G/blob/379463249c368739f81c46c1e71b8673bfcedf7c/distillation/train_hmm.py#L145). Core tensor devices follow their models, but torch.compile and CPU execution were not tested.

## Independent audit conclusion

The generic ingredients of future-aware constrained guidance, HMM/DFA continuation dynamic programming, twist-guided SMC with importance correction, and MH-corrected valid proposals have concrete official implementations. Merely transferring or combining those ingredients does not establish a new sampling principle. LSSAMP is a domain-generation comparator; the other three are direct methodological prior art. This code audit does not adjudicate every proposed novelty detail and cannot establish AMP efficacy.

All four official-repository identifications and current commit pins are resolved. Remaining HOLD items are runtime CPU/one-thread compatibility, original-paper-version reproduction, finite-budget statistical behavior, and unestablished source reuse licenses for LSSAMP/TSMC. No experiment authorization, execution or successful baseline reproduction is implied. The only failed shell read was a public GitHub DNS lookup; no denied-auth retry or privilege escalation occurred.
